# Design

## Context

`TableView` (Plugins/table/TableView.swift, 467 lines) wraps an `NSTableView` subclass, `GridView`, with a row-number column and one column per CSV column. Cells are `CellView`s that only draw text into their row's layer, which keeps opening fast. Selection is the table view's own row selection; `currentColumn` remembers the last clicked column. Clicking a title sorts through `tableView(_:didClick:)`, and the sorted column shows AppKit's sort indicator. Row drags start from any cell and move rows; column titles drag to move columns. `TablePrintView` already measures column widths from the header and the first 1,000 rows. Find selects its current match's row (`TableFind.swift`). The benchmark's largest CSV is 50,000 rows.

## Goals / Non-Goals

**Goals:** a cell-based selection that costs nothing per cell beyond a flag in `CellView`; fitting that adds no main-thread work proportional to the file; keeping `NSTableView` for scrolling, row reuse, column resizing and dragging.

**Non-Goals:** replacing `NSTableView` with a custom grid; remembering widths; selection that survives a sort as a block; accessibility for the selection beyond what cells expose today.

## Decisions

- **A selection model of our own, `TableSelection` (new file, pure value type).** It holds the current cell and an anchor in shown-row coordinates, plus a kind: a block (the rectangle from anchor to current), whole rows (`IndexSet`) or whole columns (`IndexSet`). It answers `contains(row:column:)`, the rows and columns it covers, and takes clicks, Shift-clicks, Cmd-clicks, moves (with or without extending) and Select All, clamped to the table's size. Tests drive it without a window. The table view's own selection is turned off as a visual (`selectionHighlightStyle = .none`, `allowsColumnSelection = false`). Alternative: extending `NSTableView`'s row selection with a column set; rejected because blocks and the current cell don't fit it, and every caller would still need a second source of truth.
- **Drawing.** `CellView` gets `isSelected` (accent tint at low alpha, under any find tint) and `isCurrent` (a 2-point accent ring inset in the cell). `TableView` sets both in `viewFor`, and on a selection change updates only the visible cells' flags (`tableView.rows(in: visibleRect)`), so no reload. The current cell's row number and column title get a light tint, as in spreadsheets. `CellView`'s `isNumber` (meaning the row-number column) is renamed `isRowNumber`, and alignment becomes its own property.
- **Mouse.** `GridView.mouseDown` handles clicks in data cells itself: it sets the current cell (or extends with Shift), then tracks the drag to grow a block, autoscrolling, and doesn't call `super`, so cell drags no longer move rows. Clicks in the row-number column go to `super`, so row selection and the row drag that moves rows keep working; the table view's row selection is mirrored into `TableSelection` as whole rows. Double-click still edits. Title clicks arrive through `tableView(_:didClick:)`, which now selects the column (Shift and Cmd read from the current event); dragging a title still moves the column.
- **Keys.** `GridView.keyDown` handles the arrows (Shift extends), Tab and Shift-Tab, Return and Enter (edit), Delete and Forward Delete (clear), and any other key whose characters are printable without Command or Control: it starts editing with an empty field, makes the field editor first responder, and passes the same event to it, so input methods and dead keys work. `selectAll(_:)` is overridden for Cmd+A. When editing ends, `controlTextDidEndEditing` moves the current cell by the text movement (Return down, Tab right) instead of editing the next cell.
- **Sort arrow.** A `TableHeaderView` subclass with a tracking area remembers the column under the pointer and gives it a dimmed sort indicator through `setIndicatorImage`, so AppKit lays out the title around it; the sorted column keeps its full indicator. `mouseDown` checks `NSTableHeaderCell.sortIndicatorRect(forBounds:)` for the column under the pointer: inside it cycles the sort and doesn't call `super`; elsewhere it calls `super`, which selects through `didClick` and drags to move. Sorting keeps the current cell's file row and collapses the selection to that cell.
- **Sort tools.** `sort-ascending`, `sort-descending` and `sort-none` ToolSpecs (Sort Ascending, Sort Descending, Original Order; not edit tools, no shortcuts, not in the toolbar) act on the current cell's column through the existing `sortBy(column:ascending:)`. The title's right-click menu adds the same three after a separator, after picking the clicked column as current.
- **Fitting widths and alignment, `ColumnFit` (new file).** A pure, `Sendable` pass over the header and the first 1,000 rows keeps, per column, the three longest strings by UTF-16 length and counts numbers among non-empty cells below the header (using `CSVTable.number`). It runs in `TablePlugin.load`, off the main thread, and is stored on the loaded table; `TableDocument` runs it again (on the main thread, at most 1,000 rows) after a delimiter or header change. The view measures only the kept strings with its cell font, adds padding, and clamps to a minimum of about four characters and 320 points times the zoom scale. A column is numeric when at least 80% of its non-empty sampled cells are numbers. `TablePrintView.measure` uses the same pass with its own font and limits, so there's one sampling rule. Double-click on a divider is AppKit's `tableView(_:sizeToFitWidthOfColumn:)`, answered from the sample plus the rows on screen, capped at the visible width. Alternative: measuring every sampled cell; with 200 columns that's 200,000 text measurements, too slow for opening.
- **Column edits follow the selection.** `CSVTable.removeColumns(_ indexes: IndexSet)` removes several columns in one pass over the rows, one undo step (`.rows(before)`). Delete Rows uses the file rows the selection covers. Add Row Above/Below and Add Column Before/After use the selection's first and last row or column.
- **Clearing.** `TableDocument.clearCells(rows:columns:)` sets every covered non-empty cell to empty on a copy of the rows and records one `.rows(before)` undo, then reloads; nothing happens when every cell is already empty.
- **Find.** The current match becomes the current cell (replacing the row selection in `TableFind.swift`).
- **Benchmark files.** `bench/make-fixtures.swift` writes `huge.csv` (500,000 rows of the large file's five columns, about 30 MB, so it stays editable) and `wide.csv` (200 columns by 2,000 rows); `bench/ppbench.py` adds both to its file list with labels. They're added in the first commit, so the change's own A/B run measures fitting against a base that has the same files.

## Risks / Trade-offs

- [Clearing a whole column of a 500,000-row file parses every row on the main thread] → Acceptable for now and measured by hand on `huge.csv`; background edits are the later performance change.
- [Our own mouse handling could lose AppKit behaviors: autoscroll while dragging, accessibility row selection] → Autoscroll is done with `autoscroll(with:)` in the tracking loop; row-number clicks still go through AppKit; the screen flow checks the drag.
- [Return no longer edits the next cell, which changes a habit] → It's what spreadsheets do, and typing in the next cell needs no extra key, since typing starts editing.
- [The dimmed hover indicator is drawn by AppKit, so its look follows the system and may be faint in some appearances] → Checked in light and dark in the screen flow; a custom drawing is the fallback.
- [A sample of 1,000 rows can miss a wide cell further down] → Cells are cut with an ellipsis, and double-click on the divider fits to what's on screen too.
