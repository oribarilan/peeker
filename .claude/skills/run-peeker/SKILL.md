# Run Peeker

Unit tests (`scripts/build.sh test`) check the parts. The screen tests check the built app the way a user meets it. They drive the real app, so they need the maintainer's go: an unlocked screen nobody touches for a few minutes.

## The suite

```sh
scripts/screen-test.sh                 # build, then routing and every flow
scripts/screen-test.sh pdf-edit        # only the flows named: routing, flows, pdf-edit, pdf-pages, image-edit, markdown-edit, table-edit, data-edit, recovery, viewer, theme
scripts/screen-test.sh --record        # also save a video of each flow (slower)
scripts/screen-test.sh --no-build      # test the app already built
```

It runs every flow even after one fails, prints each flow's ok and FAIL counts, and exits non-zero when a check failed or a flow didn't finish (the reason is on its line). Evidence goes to `build/evidence/run-<time>/<flow>/` (gitignored): `output.txt`, `results.txt`, screenshots, and with `--record` a video. Without video the whole suite takes about three minutes, plus the build. Read a failure's screenshots and `output.txt` before rerunning; a check that fails once and passes later is a bug to find, in the app or in the flow.

When a change is user-facing, add or update a step in a flow, with a `check` for what the user should see.

## The flows

`scripts/screen/` holds them, with `common.sh` (their shared setup), `drive.swift` and `pdf-tool.swift`. Each also runs on its own, into `build/evidence/<flow>-<time>/`.

- **routing** (`e2e-routing.sh`): launches the app once per case in benchmark mode (`PEEKER_BENCH_OUT`), which opens a synthetic file through the real catalog and config, in a window and in the Peek panel, and records which plugin opened it. It covers default lists, a dotfile, `Makefile`, a symlink, `.mp4` and a folder (no plugin), a config that moves `md` to Plain Text, a disabled plugin, and a clash. It needs no permissions and works with the screen locked. Add a line to `CASES` when routing changes.
- **flows** (`record-flows.sh`, about two minutes): a launch at login (`drive loginlaunch`) opening no window; Space on a Markdown file and a dotfile (the Peek panel), on an `.mp4` and a folder (Finder's Quick Look); the panel's first size (at most 900 × 700 points), a move with System Events that the next Space keeps, and Reset Panel Size in Settings bringing the first size back; an Editor window switched through File > Open With and the toolbar's Open With, which lists only the plugins that read the file, with an edit undone by Revert to Saved… in between; a photo's window with no Open With; the menu bar icon reporting a config clash, and its Open… bringing the Open panel to the front with no window open (`drive menuextraclick`, since macOS lets only a real click make the app active) and leaving no Dock icon after Cancel; Settings, where each change is checked in `config.json`: Image off and on, `md` moved to Plain Text and Reset, the Peek panel key recorder (with Option-Shift-Space, since other apps often hold Option-Space) and Off, a new Highlight shortcut arming the highlighter in an open PDF, the Highlight button's color arrow, Tools > Highlight Color > Green arming Highlight and remembered in the preferences (`drive menu` takes a `Menu>Submenu` path; a submenu opened through Accessibility leaves the app tracking an unseen menu, so checkmarks inside submenus stay unit tests), one recorder listening at a time, Settings reopening on the last pane, General holding Open at Login and Default app (and Permissions only the permissions), the add-extension field's placeholder (`drive placeholders`), the no-plugin alert's Open Settings, and the controls locking while the file is broken JSON.
- **pdf-edit** (`pdf-edit-flow.sh`, about 25 seconds): makes a one-page form and presses Space on it in Finder: the Peek panel's button reads Open in Peeker and a click into a field gives it no cursor. Open in Peeker opens it in the Editor, which shows the tools at once; it checks Text Box's tooltip names its key (T) and that the first Text Box shows its tip bubble, types a name, ticks a checkbox, adds a text box, draws and places a signature twice, and saves; `pdf-tool inspect` then reads the saved file. Last, a digitally signed copy (`pdf-tool signed`) opens with Text Box greyed out and the reason under the toolbar. It finds the Name field through Accessibility and places everything relative to it, so a change to the form means changing the offsets.
- **pdf-pages** (`pdf-pages-flow.sh`, about 30 seconds): on a numbered 4-page PDF (`pdf-tool pages`), rotates page 2 and deletes page 4 picked in the thumbnails with the toolbar buttons (checking the toolbar has no zoom buttons, which live in View), drags page 3 to the top (capturing the screen halfway through the final hold and checking for the accent-colored insertion bar above page 1, sampled near the bar's ends since the see-through dragged page washes out its middle), saves and opens the file in Preview for a screenshot; undoes the drag and the saved delete and saves again; then rotates and deletes once more and closes the window with Don't Save, leaving the file as saved; last, File > Insert Pages from File… adds a 2-page PDF after page 2 (typed into the open sheet with Shift-Cmd-G), Split… writes every page next to the file, and Don't Save drops the insert. `pdf-tool inspect` lists the saved pages (text and rotation) after each save. Thumbnails are found by the page numbers under them; the drag holds before it moves, or PDFKit doesn't start one.
- **image-edit** (`image-edit-flow.sh`, about 20 seconds): checks the menu bar (View and Tools, no Commands; Zoom In in View, Crop in Tools, no Edit Mode), crops right after opening a 400 × 200 PNG with the Crop button by the rectangle, checks Rotate & Resize opens below the toolbar, presses R and H in it, sets the width to 100 with Keep proportions on, applies and saves, then checks the size fields, the saved pixel size, resolution and color profile (`sips`), the info panel's Dimensions, a Preview screenshot of the file, and that Cmd+W asks nothing; then markup on a second image: M shows the strip, A and X with drags draw an arrow and a pixelated rectangle, X shows the Strength slider and S the Spotlight shape picker, and Cmd+S changes the file and keeps its size. Copy stays a unit test, so the run never touches the clipboard. Every expected size comes from the fields after the crop, so the crop drag needn't land exactly.
- **markdown-edit** (`markdown-edit-flow.sh`, about 20 seconds): presses Space on a short Markdown file in Finder and checks the Peek panel's text (`drive value`) has the bold word without `**` or `#`; opens it in the Editor, clicks just right of its last line, types and saves, and compares the file byte for byte with what it should hold; clicks the `[ ]` task box and checks the line reads `[x]`, the file still has `[ ]`, and Cmd+W asks to save (Cancel), then saves again; last, clicks Later in the sidebar outline and checks `drive selection` puts the cursor at the start of the `## Later` line and `drive marked` shows Later marked, clicks the text under `# Notes` and checks Notes is marked, compares the sidebar button's frame with the outline's (`drive frame Peeker AXButton Sidebar`, `drive frame Peeker AXTable`) so the button sits over the sidebar, and that Cmd+W asks nothing. Text is found with `drive textframe`, so the clicks follow the layout; the line number counts laid-out lines, so the fixture keeps every line short.
- **table-edit** (`table-edit-flow.sh`, about 25 seconds): presses Space on a four-line CSV in Finder and checks the Peek panel holds an `AXTable` with the cell Cake (`drive tree`); opens it in the Editor, checks the column titles are the header's (buttons named name and price) and the rows are in file order, double-clicks Cake's price, types 9, Return and Escape, saves, and compares the file byte for byte with the one changed field; clicks the price title and checks Bread sorts to the top and Cmd+W asks nothing; then reopens it, checks View has Header Row and Commas checked (`drive menuitems`), turns Header Row off (name shows as a cell) and on again, and checks Tools > Add Row Below makes Cmd+W ask to save, and Don't Save leaves the file as saved. Cells are found as static text with `drive frame Peeker AXStaticText`: the edited cell sits in Cake's row and 3.50's column, since the info panel's Rows count also reads 4.
- **data-edit** (`data-edit-flow.sh`, about 35 seconds): presses Space on a short JSON file in Finder and checks the Peek panel holds an `AXOutline` with the key version and the value app (`drive tree`); opens it in the Editor, checks the column titles (buttons named Key and Value), that deps reads 1 key and its child a shows (the first level opens), and the toolbar's Add Item; double-clicks version's value, types 2 and Return, saves, and compares the file byte for byte with the one changed value; chooses View > Show Text and checks its checkmark (`drive menuitems`) and that the text (`drive value`) has the saved value, chooses it again to go back to the tree, and checks Cmd+W asks nothing; last, a file missing a comma opens as text with the bar reading Line 3: Expected a comma or }, and choosing Show Text leaves it unchecked and the bar up, since `drive menuitems` doesn't say whether an item is enabled. Then Space on a YAML file shows a tree with its keys and its list's items, and a binary property list (made with `plutil -convert binary1`) opens as a tree with its key and value, whose Show Text has the XML form and ignores typing. Cells are found as static text with `drive frame Peeker AXStaticText`: version's value sits in app's column, halfway between app's row and deps' 1 key, since deps' child a also reads 1 and the sidebar's outline also lists version.
- **viewer** (`viewer-flow.sh`, about 50 seconds): the hover tint on a PDF's thumbnails (`drive move`; page 1 clicked to select it, then captures of page 2's thumbnail differ with the pointer over it while the page itself stays white, and page 1's don't), Cmd+F with the thumbnails still focused and Find Next (reading the bar's "1 of 4", and checking the bar sits below the toolbar), Cmd+P in a PDF, a text file, a Markdown file and an image (the print sheet appears and is cancelled), View > Hide Sidebar on the text file (still hidden after an edit and Cmd+S, shown again by the toolbar's sidebar button), a window stopping at its minimum size, and Wrap Lines' checkmark in View (`drive menuitems`), a password-protected PDF (`pdf-tool locked`) unlocked through its lock screen, then Actual Size (Cmd+0) and Zoom to Fit (Cmd+9) on it, Actual Size and zooming out on an image, a GIF that plays, pauses on a click and plays on, and does the same from View > Play Animation (its checkmark following), a two-page TIFF whose selected thumbnail follows Page Down and Page Up (`drive marked`), text zoom and Wrap Lines kept across a quit and relaunch (`drive textframe` heights), Save As… through its sheet (the window follows the copy, and Cmd+S then changes only the copy), and Actual Size on a 6000 × 4000 photo of one-pixel stripes, whose middle must keep its stripes (`drive contrast` on the screenshot). Zoom and the GIF are checked by comparing window screenshots, so their checks only say the picture changed or didn't; look at the screenshots too.
- **theme** (`theme-flow.sh`, about 40 seconds): opens a Markdown and a text file and presses Space on another Markdown file, all in System colors; clicks the Paper card in Settings > Appearance (`drive press Peeker Paper`) and checks `config.json` says `"textTheme": "paper"`; then the open files, shown again with `open -a` (which brings an open file's window or tab forward rather than reopening it), and the Peek panel must look different and have Paper's background (F7F3EA, or 23211D when the system is dark); a Python file's `def` must be drawn near System's keyword color and then Paper's (`drive closest` on a screen capture of its `drive textframe`, within 40 per channel). Then it presses Dark in the Appearance control and Light in Text appearance (`drive press Peeker Light "AXRadioGroup=Text appearance"`, since both controls have the same segments), checks the config, that Settings turned dark, and that the Markdown window shows Paper's light page beside a dark sidebar; last, a config with `"textTheme": "nope"` must show as one problem in the menu bar icon and put both files back to their System color. Colors come from window screenshots through `drive pixel`, at 75% across and 80% down, right of the sidebar and below the short text; a layout change that puts something else there means moving the spot.
- **recovery** (`recovery-flow.sh`, about 25 seconds): types into a text file and fills the form's Name field, waits for both recovery records, kills the build under test with SIGKILL and launches it again. Both documents come back as tabs with their edits; closing each asks to save, and Don't Save empties the recovery folder. A recovered file that's gone (its text goes to the clipboard) stays a unit test, so a run never touches the clipboard.

Every flow runs Peeker with a throwaway config through `PEEKER_CONFIG` and a throwaway crash-recovery folder through `PEEKER_RECOVERY`, so the user's own config and recovery records are never read or written. State the app keeps in its preferences (the sidebar's, Settings' last pane, the Peek panel's frame, seen tips, and text zoom and wrapping) is shared with an installed Peeker, so each run starts without it and puts the user's back when it ends. It drives and quits only the build under test. pdf-pages and image-edit open their saved file in Preview for a screenshot and close only that window, quitting Preview only when it wasn't running before.

## Driving by hand

`drive.swift` does the pieces; its commands are listed at the top of the file. Build it with `swiftc -O scripts/screen/drive.swift -o build/run-tools/drive` (the flows do this themselves). Keys, clicks and typing go out only while the named app is in front, as in `drive keys Finder space`. Wait on state rather than time: `drive wait Peeker window form.pdf`, `drive wait Peeker sheet --gone`, `drive wait Peeker control "Text Box"`. `drive focus Peeker` shows where the keyboard is when typing doesn't arrive. `drive pixel shot.png 0.5 0.5` prints a screenshot's color at the middle as sRGB hex, for checking what color something was drawn in.

Launch the app yourself with `open --env PEEKER_CONFIG=<scratch config> --env PEEKER_RECOVERY=<scratch folder> -a <Peeker.app> [file]`; both apply only when the app isn't running yet. A full-screen capture is `screencapture -x out.png`, and a recording is `screencapture -v -V <seconds> -x -k -C out.mov`, then `avconvert --preset Preset1920x1080 --source out.mov --output out.mp4`.

## Requirements and traps

- **A locked screen blocks everything visual.** Screenshots come back black, Accessibility reports no windows, and keys go to the lock screen. The flows refuse to start then; only routing runs while locked.
- **Another copy of Peeker** (an installed one) makes the flows refuse to start, so the user's windows are never touched. Quit it first.
- The terminal running the tests needs Accessibility (keys, the Accessibility tree) and Screen Recording (captures), and the first `drive select` asks to let it automate Finder.
- Peeker itself needs Accessibility for Space to reach it. Without it, every Space goes to Finder's Quick Look and the Space checks fail with `Quick Look`. The build is signed with a team ID, so the permission survives rebuilds.
- A bare Space only reaches Peeker while Finder is frontmost and no text field has focus, which is why the flows select files through Finder first.
- **Modifier keys.** A synthetic key event's flags leave its modifiers set in the system's state; `drive keys` releases them afterwards, and `drive type`, `click` and `drag` send no modifiers. Any other tool that posts key events must do the same, or later typing arrives as shortcuts.
- **Stopping a run.** Ctrl-C (or SIGTERM) stops a flow: it answers Don't Save, quits the build under test and kills the recorder, losing that video, since `screencapture` can't stop early and keep its file. A flow started with `&` from another script ignores SIGINT, so use SIGTERM there.
